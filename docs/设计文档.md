# 电子元件库设计文档

个人物料库：账号登录后，物料、物料盒、项目 BOM 按用户隔离。导入 BOM 只记录需求并与自有库存匹配，不改库存。立创商城库存和价格只用于展示。

后端是 FastAPI + SQLAlchemy，表定义在 `backend/app/models.py`。启动时 `create_all` 建表。不做数据库迁移：表结构变化后，旧库需要删掉重建。默认 SQLite，可用 `DATABASE_URL` 改为 MySQL（`mysql+pymysql://...?...charset=utf8mb4`）。

## 表关系

```text
users
  ├── boxes
  │     └── items          一条物料最多占一个格子；未入盒时 box_id 为空
  ├── items
  └── projects
        └── project_lines  删除项目时明细级联删除
              └── matched_item_id → items   只是引用，删除物料前由程序置空
system_configs             全局键值，不按用户隔离
```

业务数据都带 `user_id`。查询必须限定当前用户。物料和物料盒写入时写入当前用户的 `user_id`。`system_configs` 是整库一份，存放数据库位置、数据库名字、是否允许注册和辅助 AI 的接口配置。

SQLite 连接时打开外键。`project_lines.project_id` 声明了 `ON DELETE CASCADE`。其余外键没有数据库级联，删除顺序由程序保证。

## 表设计

时间一律存 UTC。空立创编号在写入前变成 `NULL`，不存空字符串。SQLite 和 MySQL 的唯一索引都允许多个 `NULL`。

### users

登录账号。

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | 整数 | 主键 | |
| email | 字符串(255) | 唯一、索引 | 登录名，小写保存。自助注册必须是邮箱；初始管理员是 `admin` |
| password_hash | 字符串(255) | | bcrypt |
| is_admin | 布尔 | 默认否 | 管理员可管理账号和切换数据库 |
| must_change_password | 布尔 | 默认否 | 为真时只能访问 `/api/auth/me`、`/api/auth/password`、`/api/auth/logout`，其余接口返回 403 |
| session_token | 字符串(64) | | 随机值，写进会话 Cookie。改密码或删账号后旧 Cookie 失效 |
| created_at | 时间 | | |

没有邮件找回密码。

### boxes

一个用户可以有多个物料盒，盒子之间行列数可以不同。

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | 整数 | 主键 | |
| user_id | 整数 | 外键 users.id，索引 | 所属用户 |
| name | 字符串(120) | 与 user_id 联合唯一 | 同一用户下名称不能重复 |
| rows, cols | 整数 | | 创建时指定，合法范围 1–100。坐标从 1 开始 |
| remark | 文本 | 默认空 | |
| created_at | 时间 | | |

唯一约束：`(user_id, name)`。

### items

库中一种料及其位置。自有库存是 `quantity`。

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | 整数 | 主键 | |
| user_id | 整数 | 外键 users.id，索引 | |
| lcsc_code | 字符串(64)，可空 | 与 user_id 联合唯一 | 立创编号，如 `C105580`。一律存大写，空为 NULL |
| mpn | 字符串(255) | 默认空 | 厂家型号 |
| name | 字符串(255) | 默认空 | 商品名称 |
| brand | 字符串(255) | 默认空 | 品牌 |
| footprint | 字符串(255) | 默认空 | 封装原文 |
| category | 字符串(255) | 默认空 | 类目，优先用归一后的中文类目 |
| value | 字符串(255) | 默认空 | 标称值，如 `10kΩ`、`1uF` |
| params | 文本 | 默认空 | 参数原文，给人看 |
| specs | 文本 | 默认 `{}` | 结构化参数，JSON 对象 |
| quantity | 整数 | 默认 0，且 ≥ 0 | 自有库存 |
| min_stock | 整数 | 默认 0，且 ≥ 0 | 低库存阈值。大于 0 且 `quantity` 小于它时算低库存 |
| box_id | 整数，可空 | 外键 boxes.id | 空表示未入盒 |
| row, col | 整数，可空 | | 盒内坐标。未入盒时必须为 NULL |
| datasheet_url | 文本 | 默认空 | |
| image_url | 文本 | 默认空 | 本机图片地址，形如 `/api/media/lcsc-C105580.jpg`。外链只在下载成功后改成这个地址 |
| remark | 文本 | 默认空 | |
| created_at, updated_at | 时间 | | |

唯一约束：

- `(user_id, lcsc_code)`：同一用户有值的立创编号只能一条。
- `(box_id, row, col)`：同一盒子的同一格只能一条。未入盒时这三列都是 NULL，可以有多条。

`specs` 是 JSON 对象，键和显示方式来自当前用户的类目配置，值是字符串。未配置的类目、配置里没有的键、空值都不入库。`specs` 不参与库存匹配，匹配仍看编号、型号、封装、标称值和类目。

### spec_categories

每个用户一套类目配置。注册、管理员建账号、以及第一次出现这张表时，都会写入一份默认类目。

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | 整数 | 主键 | |
| user_id | 整数 | 外键 users.id，索引 | |
| name | 字符串(120) | 与 user_id 联合唯一 | 类目名称，对应 `items.category` |
| lcsc_keywords | 文本 | 默认 `[]` | JSON 数组。立创最后一级目录名包含其中一词就归入此类目，靠前的类目优先 |
| fields | 文本 | 默认 `[]` | JSON 数组。每项含 `key`、`label`、`type`、`unit`、`options`、`aliases`、`required` |
| sort_order | 整数 | 默认 0 | 列表顺序，也是立创归类的优先顺序 |
| created_at, updated_at | 时间 | | |

`key` 只能是小写字母、数字和下划线，最长 32 位，同一类目内不能重复。`type` 为 `text`、`number` 或 `select`。`number` 可带 `unit`，保存时去掉末尾单位后必须是数字。`select` 的值必须在 `options` 里。`aliases` 用来从立创或 BOM 参数名里抽取，留空时用显示名。

默认类目是电阻、电容、电感、二极管、MOS、三极管、连接器、电源。前六个带原来的文本字段，连接器和电源只有立创关键词、没有字段。用户可以增删改，改名时会把该用户物料里的同名 `category` 一并改掉。删除配置不改已有物料；这些物料再次保存时，按当时的配置清洗 `specs`。

### system_configs

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| key | 字符串(64) | 主键 | `database_location`、`database_name`、`allow_register`、`deepseek_api_key`、`deepseek_base_url`、`deepseek_model` |
| value | 文本 | 默认空 | |
| updated_at | 时间 | | |

数据库位置和名字只在当前库是 SQLite 文件时用来切换。辅助 AI 的三项在任何库里都会写入；已有键不覆盖。API Key 为空表示未启用智能建议。接口地址默认 `https://api.deepseek.com`，模型默认 `deepseek-chat`。环境变量只在对应键还不存在时作为初始值。

### 删除与位置

| 动作 | 结果 |
| --- | --- |
| 移出盒子 | 只清空 `box_id`、`row`、`col` |
| 删除盒子 | 盒内物料变为未入盒，再删盒子。不删物料 |
| 缩小行列 | 已有物料的行或列超出新范围则拒绝，提示先移走 |
| 删除物料 | 先把指向它的 `matched_item_id` 置空，再删物料。它的位置和出入库流水一起删除，统计里的用量随之减少，前端确认框会提示 |
| 删除账号 | 先清空指向其物料的 `matched_item_id`，再删该用户的明细、项目、物料、物料盒、类目配置和用户 |
| 删除项目 | 明细随外键和 ORM 级联删除 |

不能删除当前登录账号，也不能取消或删除最后一名管理员。

坐标不合法（空、小于 1、超出当前行列）的物料不占格子，出现在地图的 `invalid_items`。

## 逻辑设计

### 启动与库

`prepare_database` 在应用启动时执行：

1. 启动地址先看环境变量 `DATABASE_URL` 旁的 `active_database.json`。文件里有合法的位置和文件名时，用那份 SQLite；否则用环境变量。默认 `sqlite:///./data/app.db`。
2. SQLite 文件不存在则创建目录。MySQL 库不存在则先 `CREATE DATABASE ... utf8mb4`。
3. `create_all` 建表。
4. 库里没有任何管理员时：账号 `admin` 已存在则设为管理员，不改密码；不存在则写入 `admin` / `admin`，`must_change_password` 为真，并写一份默认类目。
5. 把当前位置、文件名，以及 DeepSeek 的 API Key、接口地址、模型写入 `system_configs`（已有键不覆盖）。API Key 的初始值来自 `DEEPSEEK_API_KEY`。

### 登录与账号

会话 Cookie 名 `cms_session`，HttpOnly，SameSite=Lax，路径 `/`，14 天。值是 `userId.sessionToken.expires.hmac`，密钥为 `SECRET_KEY`；未设置时自动生成随机密钥，存在数据库同目录的 `secret_key` 文件里。每次请求都核对 `sessionToken` 与用户表一致，所以删号后同 id 的新账号不会继承旧 Cookie。`COOKIE_SECURE=1` 时加 Secure。

- 自助注册：默认关闭，由 `system_configs.allow_register` 控制，`GET /api/auth/options` 告诉前端是否显示注册入口。邮箱转小写，须符合邮箱格式，密码 6–72 字节，注册后即登录。`is_admin` 为否。
- 登录：账号或邮箱均可，先转小写再查。失败统一为「账号或密码错误」。15 分钟内同一来源同一账号失败 10 次，或同一来源失败 30 次，返回 429。
- 改密码：校验原密码，新密码 6–72 字节。成功后换新 `session_token`，当前会话重新签发 Cookie，其他设备失效。
- 管理员创建的账号不必是邮箱，但不能含空白，最长 255。密码至少 6 位；修改时密码为空表示不改。

未登录访问业务接口返回 401。非管理员访问账户管理和基本设置返回 403。参数配置（类目）按用户隔离，普通用户也能进。

### 物料与放置

新增和修改都提交完整字段，不是部分更新。`apply_fields` 的规则：

- 立创编号去空白并转大写，空则存 NULL。同一用户已有该编号则拒绝。BOM 导入、匹配、筛选也都按大写处理。
- 没有盒子时，行和列强制为 NULL。
- 有盒子时，盒子必须属于当前用户，行和列必填，且在 1 到盒子行列数之间。格子已被其他物料占用则拒绝。
- `specs` 只保留当前用户该类目配置里的键。数字字段去掉末尾单位后必须是数字，字典字段必须命中选项，必填字段不能空。手填保存时不符合就拒绝；立创自动写入时丢掉不符合的值。空值丢掉，再按键名排序写成 JSON。读出时，所有已配置类目都会用 `params` 补上还没有的键。
- 库存不能为负数。

列表按编号、型号、名称、封装、类目、备注做包含筛选，分页，每页最多 100 条。`low_stock=true` 只看低库存。返回里带 `low_stock_count`（当前用户全部低库存物料数）和每条的 `low_stock`。

关键词搜索参数 `q`（`app/services/search.py`）：

- 先按空白切词，再把「10k电阻0603」这类粘在一起的输入拆成「10k / 电阻 / 0603」。
- 每个词识别成一种条件：类目名（含常见英文和别名）、标称值（`10k`、`4k7`、`0.1uF`、`100n`、`10uH`，换算成同一单位比较）、封装（片式尺寸和 SOT/SOD/SOP/QFN 等）、耐压等参数值（`50v`），其余当作编号、型号、名称、备注的包含匹配。
- 只写数值不写类目时，按单位推断类目：Ω 是电阻，F 是电容，H 是电感。
- 所有条件都满足才算命中。没有命中就返回空列表，不退回到模糊结果。
- 返回 `hints`，前端显示成「识别为：电阻 / 10kΩ / 封装 0603」。

`GET /api/items/export` 接受与列表相同的筛选和 `q`，不分页，导出 `.xlsx`。以 `=`、`+`、`-`、`@` 开头的单元格前加 `'`，防止被 Excel 当成公式。

立创查询先请求 `https://lceda.cn/api/eda/product/search` 拿商城最后一级目录，再请求 `https://wmsc.lcsc.com/ftps/wm/product/detail` 补参数。两边都没有该编号时接口返回「查询失败，请手填」。映射规则：

- 型号、英文名称、品牌、标准封装分别取商品字段。
- 类目只看立创最后一级目录名，用当前用户的立创关键词归类。归不上则保留该目录名。
- 标称值取参数名「阻值 / 容值 / 电感量 / 电感值」或其英文名。
- `params` 为 `参数名: 参数值`，用 `；` 连接。`specs` 按该类目字段的别名从这些参数里抽取。
- 商城库存和价格只返回给前端，不写入 `quantity`。
- 商品图片下载到当前数据库文件旁边的 `images/<库名>/u<用户id>` 目录，按立创编号或物料编号命名。只允许 http/https，目标和每次跳转后的地址都必须解析到公网 IP，最多跳转 5 次，单张最大 5MB。接口里的 `image_url` 改为 `/api/media/文件名`。文件已存在则不再下载。下载失败时不把外链交给页面，避免离线打开物料盒时再请求外部图片。登录后通过 `GET /api/media/{文件名}` 读取本人目录下的文件，别人的文件返回 404。

物料抽屉里点「查询」会回填资料，并保留用户已填的库存、盒子、行列和备注。保存仍走物料新增或修改接口。

### 物料盒地图

`GET /api/map` 可带类目和项目。

- 统计是物料种类数、盒子数、库存合计、库存总价值和低库存物料数，不受类目筛选影响。
- 每个盒子按行优先铺满格子，空格也返回。
- 类目筛选时，其它类目的格子标记为变淡，仍然占用，不能当成空格放入。
- 未入盒物料单独列出。
- 传入项目时，只给 `matched`、`insufficient`、`suggested` 且已选中物料的明细标位号。位号按逗号、中文逗号和空白拆开。没有位号则不标。其余候选不标。

### 结构化参数

从 `参数名: 参数值`（中英文冒号，分号或换行分隔）里按别名抽取。比较前去掉空格和标点并转小写。短别名（不超过 2 个字符）只匹配参数名的前缀或后缀，避免 `id` 误伤其它词。同一参数名只取第一次出现的值。

立创查询、按编号预填、以及旧数据回填都走这套抽取。用户保存时如果类目变了，不属于新类目的键会被丢掉。

### BOM 导入

只接受 `.xls`、`.xlsx`，最大 10MB。先读成字符串矩阵，合并单元格的值铺满整个区域，再识别格式。失败不创建项目。

识别顺序：

1. 前 15 行出现「立创商城BOM报价单」，或前 40 行有同时包含「商品编号」和 `Designator` 的表头 → `lcsc_quote`。有标题但找不到表头则失败。
2. 否则表头同时含 `Manufacturer Part`、`LCSC Price`、`Value` → `easyeda_v131`。
3. 两种都不符 → 「无法识别文件格式」。
4. 格式认得但没有有效明细 → 「没有可导入的物料明细」。

表头比较忽略大小写和多余空白。

立创 EDA：

| 列 | 写入 |
| --- | --- |
| No. | `line_no` |
| Quantity | 单板用量，导入时需求总量先写成同一数字 |
| Footprint、Manufacturer、Manufacturer Part、Value | 封装、品牌、型号、标称值 |
| LCSC Price | 只用于识别，不入库 |

其余有值的列拼进 `params`，格式 `列名: 值`，分隔符 `；`。立创编号、位号、商品名称、类目为空。采购套数先写 1。跳过全空行，以及型号、标称值、封装、品牌都空的行。

立创商城报价单从表头前的单元格读取：

- `BOM名称：` → 项目名，没有则用文件名
- `采购套数：` → 采购套数，缺省 1
- `BOM配单编号：` → `order_no`

| 列 | 写入 |
| --- | --- |
| ID，否则 No. | `line_no` |
| Designator | 位号 |
| Quantity | 单板用量 |
| 商品编号 | 立创编号 |
| 型号，否则 Manufacturer Part | 厂家型号 |
| 品牌，否则 Manufacturer | 品牌 |
| 封装，否则 Footprint | 封装。两者都有且不同时，把 `原始封装: ...` 追加到参数 |
| 目录、商品名称 | 类目、商品名称 |
| 原参数、参数 | 拼进参数原文 |

标称值优先取参数里的「阻值 / 容值 / 电感量 / 电感值」后第一段；否则在 `Name` 看起来像标称值（含数字，且含 Ω、ohm、F、H，或以 k、m 结尾）时用 `Name`；型号不会被当成标称值。

有效行至少要有立创编号、型号、位号、商品名称、标称值之一。报价单里的「购买数量」列不入库。需求总量在导入时按单板用量 × 采购套数计算，匹配时会再算一遍。

导入成功后立刻按当前用户的全部物料做一次匹配。

修改采购套数（至少为 1）会把每条明细的需求总量改成 `单板用量 × 新套数`，并重新匹配。重新匹配按钮走同一套计算。删除项目会同时删掉它的明细，不影响物料库。只能删除自己的项目。

### 库存匹配

匹配读取该用户全部物料和该项目全部明细，写回 `match_status`、`matched_item_id`、`suggestions_json`、`matched_at`。不改 `items.quantity`。

`system_configs` 里的 `deepseek_api_key` 为空时不做精确匹配，也不做规则预筛。每条明细写成空状态、无选中物料，`suggestions_json` 的 `source` 为 `disabled`。项目详情接口此时也不返回已有的匹配字段，页面上的 `ai_enabled` 为假。在系统配置里保存密钥后立刻生效，导入、改套数或点「重新匹配」才会真正匹配。

配置了密钥时，精确命中优先于替换建议。精确命中的明细不会发给 DeepSeek。

| 状态 | 含义 |
| --- | --- |
| matched | 精确命中，且选中物料库存 ≥ 需求总量 |
| insufficient | 精确命中，但库存小于需求总量 |
| suggested | 无精确命中，规则或 DeepSeek 给出了候选 |
| not_found | 无精确命中，也没有可展示的候选 |

精确命中满足其一即可，同一物料只计一次：

- 立创编号去空白后忽略大小写相等，且两边都非空。
- 否则厂家型号去掉全部空白后忽略大小写相等，且两边都非空。

多条命中时选一条，优先级从高到低：库存够且封装相容、库存够、封装相容、库存更大、id 更小。编号命中时理由是「立创编号一致」，否则「厂家型号一致」。`source` 为 `exact`。`exact_hits` 含全部命中，选中项在前。`candidates` 为空。

封装是否相容：两边都能抽出封装主名时比较主名；否则比较去掉空白后的原文，且原文都要非空。

封装主名从封装文本提取：

- 片式尺寸 `0201` `0402` `0603` `0805` `1206` `1210` `1812` `2010` `2512`。`R0603`、`C0603`、`LED0603` 都是 `0603`。
- `SOT-23-3` 与 `SOT23` 都是 `SOT-23`；`SOT-223` 保持 `SOT-223`。
- `SOD-123` 与 `SOD-123FL` 彼此不同。
- `SOP`、`SOIC`、`SSOP`、`TSSOP`、`ESOP`、`MSOP`、`QFN`、`DFN`、`LQFP`、`TQFP`、`QFP`、`TO` 保留后面的数字，写成 `名称-数字`。
- 以 `SMA`、`SMB`、`SMC` 开头的用该名字。

标称值归一：转小写，`μ` / `µ` 视为 `u`，去掉空白以及 `ohm` / `Ω`。因此 `5.1kΩ` 与 `5.1k`、`4.7μF` 与 `4.7uF` 相同。

类目标签看 `category`，为空时明细再看商品名称，库内物料再看名称。关键词：电阻、电容、电感、二极管、MOS、三极管、LED、连接器、电源，含常见英文。

未精确命中的库内物料，满足以下任一即入候选，最多 20 条：

- 封装主名相同且都非空。
- 标称值归一后相同且都非空。
- 类目标签有交集。

排序：命中条件数多的在前，然后库存大，然后 id 小。理由由命中的条件拼成，例如「封装主名同为 0603，标称值同为 10kΩ」。封装主名都有但不相同，风险加「封装」。类目都有但无交集，风险加「类目」。没有可用候选则为 `not_found`，`source` 为 `rule`。有候选则为 `suggested`，选第一条为 `matched_item_id`，`source` 为 `rule`。

DeepSeek 只处理未精确命中、且已有规则候选的明细。接口地址和模型取系统配置里的 `deepseek_base_url`、`deepseek_model`，请求 `{接口地址}/chat/completions`，直连接口，不使用系统代理。每批最多 5 条，最多 4 批同时发出，单批读取超时 60 秒。项目和明细先写入并提交，再在工作线程里发起这些请求，避免网络等待占着数据库锁或堵住其他页面。模型只能从该明细的候选 `item_id` 里选。`suitable` 不为真，或编号不在候选里的，丢弃。风险只保留：耐压、精度、功率、温度、封装、库存。

- 本批请求失败：该批改用规则结果。
- 请求成功但没有可用选择：`not_found`，`source` 为 `ai`。
- 有可用选择：`suggested`，`source` 为 `ai`，理由优先用模型原文。

`suggestions_json` 形如：

```json
{
  "source": "exact",
  "reason": "立创编号一致",
  "risks": [],
  "exact_hits": [],
  "candidates": []
}
```

`exact_hits` 与 `candidates` 的元素含物料 id、立创编号、型号、名称、封装、标称值、类目、库存、盒子名、行列、是否合适、理由和风险。详情接口把这些记录收成位置文案，形如 `型号 · 盒子 第R行第C列（库存 N）`；没有盒子时位置为「未入盒」。`stock` 取第一条命中或第一条候选的库存。

「一键出库」只扣 `matched` 和 `insufficient` 且已选中物料的明细，`suggested` 必须先点「使用替换器件」确认。单行出库和「补充库存 / 减扣库存」同样要求已确认，否则返回 400。「全部加入物料库」按需求数量把每行入库：库里能找到对应物料就加库存，找不到就新建。这两个操作都可以重复执行，每次都会再入库或再扣一次，前端执行前会弹确认框。

明细上「按编号加入物料库」只在有立创编号，且状态为 `not_found` 或 `suggested` 时出现。该操作只预填表单，库存固定为 0，不入库。立创查询失败时用 BOM 字段预填，并提示核对。用户保存后走普通新增，再重新匹配。

### 切换 SQLite

仅管理员。位置必须是目录（可以尚不存在），名字只能是以 `.db` 结尾的文件名，不能带路径。

保存时一并写入 API Key、接口地址和模型。目标与当前文件相同：更新 `system_configs`，并写 `active_database.json`，不更换连接。只有位置或名字变化时才切换数据库。切换到新库时，这些配置写入新库。

读取配置时 API Key 只返回首尾几位，另给 `deepseek_api_key_set`。保存或测试时提交的仍是这个遮挡值，就沿用库里的原 Key。

「测试」把页面上当前填写的 Key、接口地址、模型和一段任意文本发给 `{接口地址}/chat/completions`，把模型原文显示出来。这不走物料匹配提示词，也不写入数据库。Key 为空、内容为空或接口失败时返回 400。

目标是另一个文件：新建连接，跑一遍建库和初始管理员，写入该库的位置配置，再替换进程内的引擎。失败则丢弃新连接，当前库不变。切换成功后清掉当前 Cookie，返回 `database_switched: true`，前端跳回登录页。指针文件写在环境变量所指向的 SQLite 所在目录；下次启动优先读这个指针。

当前连接不是 SQLite 文件时，不能通过这个接口切换。

### 备份

`GET /api/settings/backup`，仅管理员。用 sqlite3 在线备份接口复制当前库，连同 `images/<库名>` 目录打成 zip：`database/<文件名>` 和 `images/<库名>/...`。不包含 `secret_key`，恢复后需要重新登录。当前库不是 SQLite 文件时返回 400。
